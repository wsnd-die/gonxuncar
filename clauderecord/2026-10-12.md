#### V1.32.0 - 2026-10-12
- **修改类型**：新增（**航向环改造：串级 PID + S 型轨迹 + 双前馈 + 中断步进**）
- **涉及模块**：算法层 / **`algorithm/angle_ctrl.c` + `.h`（原地改造，未新建文件）**、
  `algorithm/arc_path.c`；应用层 / `app/NavigationMecanum.c` + `.h`、`app/worker_task.c`；
  生成区 / `Core/Src/tim.c`、`Core/Inc/tim.h`、`Core/Src/stm32g4xx_it.c`、`Core/Src/main.c`
- **修改内容**：把 `Nav_GoToWorld()` 里那段**手写单环航向 PD** 换成**带 S 型轨迹 +
  双前馈的串级控制器**，步进放进 **TIM7 中断（1 kHz）**。按用户要求**改造既有
  `angle_ctrl`，不另立模块**。
  ① **数据源 HWT906 → OPS9**（用户明确要求）：`angle_ctrl` 内部自己
     `locator_ops9.get_pose()` 取 `pose.yaw`/`pose.wz`，与导航同源。原来那条
     `Angle_Fuction()` 喂 `imu_hwt906` 的链**整段删除**（那三处 init/update/get_pose）。
  ② **单位 deg → rad**：与 `pose.yaw`/`pose.wz`/`Mecanum_Calc_Full_V()` 的 w 统一，
     不再有 deg/rad 换算。`g_angle_target_yaw` 的契约量纲随之改成弧度。
  ③ **S 型轨迹发生器**：三阶临界阻尼参考模型，状态 `(θ_ref, ω_ref, α_ref)`，
     `α̇ = K³·e − 3K²·ω − 3K·α`（三重极点都在 −K ⇒ 无超调、C² 连续）。ω 上限带
     `√(2·α_max·|e|)` 制动力上限防末段冲过头；α 必须限幅（t=0⁺ 时 α̇=K³Δθ）。
     K 由物理上限反推：`K ≤ √(α_max/(0.231·Δθ))` ⇒ 起步 3.5。
  ④ **串级 PID**：外环角度 `ω_cmd = Kp_θ·e_θ + **ω_ref**`（★速度前馈）；
     内环角速度 `w = Kp_ω·e_ω + I_ω + **K_ff·α_ref**`（★加速度前馈）。外环 Ki=0
     （前馈已消稳态误差源）；内环 Ki 小量保留。**两级都不设 D** —— 内环反馈本身
     就是外环误差的导数（串级的价值），再对误差差分会把噪声放大两遍。
  ⑤ **★ 删掉致命坏点 `gyro_scale = 0.05`**：原版把内环反馈缩成 5%，等效于把
     Kp_ω 砍成 1/20，**串级形同虚设**（串级只剩个摆设）。
  ⑥ **复用工程既有的 `algorithm/pid.c`**：两级都是 `pid_type_def` + `PID_calc()`。
     ⚠ `PID_calc()` **无 dt 项** ⇒ **只有 I 要按采样率折算**（`PID_init` 里传
     `ANG_KI_W * ANG_DT`），P 与 dt 无关原样传。⚠ `PID_calc()` 的状态在调用方
     结构体里、**可重入**；不可重入的是 `PID_Filter()`（文件级 static 全局），本文件不用它。
     死区用「把 set 拉到 ref 上」实现（PID 内部误差真为 0，积分也不再累）。
  ⑦ **中断/任务分工**：ISR 只算（纯浮点），任务取 `Angle_GetW()` 后
     `Mecanum_Calc_Full_V` + `Send_commandmotor` —— **因为 `Send_commandmotor()`
     末尾有 `osDelay(5)`、CAN 发送链内有 `osDelay(1)`，都不能在 ISR 里调用**。
     共享面收敛到 3 个 volatile 词 + 1 个心跳（Cortex-M4 单字读写天然原子）。
  ⑧ **接入 `Nav_GoToWorld()`**：等**首个有效位姿**再 `Angle_Enable(target_yaw)`
     （内部把 θ_ref 初始化到当前位姿、目标写成 `yaw_now + wrap(target−yaw_now)`
     走近路 ⇒ 起步无跳变，且**与 OPS9 的 yaw 零点是否标定无关**）；三个出口
     （打断/超时/到达）各加 `Angle_Disable()`；`Nav_Cricle`/`Arc_Run`/`Arc_Abort`
     入口加**防御性** `Angle_Disable()`（它们的航向律语义不同，不被改造）。
  ⑨ 回退开关 **`NAV_YAW_CASCADE`**（范式照抄 `NAV_XY_PROFILE`）：置 0 ⇒ 逐字节
     回到原来的手写 PD。**回退成本 = 一行宏。**
  ⑩ 顺手补 `ovs_yaw` 过冲仪表 —— 原 `[NAV] ARRIVE ... ovs=` **只统计 x/y、
     没有 yaw**，而这次换的正是航向环，没有它无从 A/B 对比。
- **影响范围**：**航向控制律**（转向的超调/平滑度/到位时间）。平移 X/Y 链
  （`NAV_AxisRef` / `NAV_Ramp` / 世界转车体）**逐字节未动**。
- **验证状态**：待测试（`--clean-first` 全量重编通过，零新增告警）
- **备注**：⚠ **1 kHz 只算 ≠ 闭环带宽提高 10 倍** —— 指令实际到达电机的速率仍是
  任务下发率（约 66~100 Hz），1 kHz 算出的指令约 93% 被丢弃。ISR 的收益是
  「**下发时拿的是最新鲜的指令**（相位滞后 10~15ms → ~1ms）+ 前馈轨迹光滑 +
  控制律与任务环解耦」。**内环带宽目标要按 66~100 Hz 算**。要做到真带宽需把
  CAN 下发也改成非阻塞塞进 ISR（Phase 2，风险高，本次不做）。
  ⚠ **CubeMX 重新生成会覆盖** TIM7 的相关生成区 —— 需要在 CubeMX 里补：
  `Timers → TIM7`：Internal Clock、**Prescaler=169**、**Counter Period=999**
  （⇒ 1 kHz）、`NVIC → TIM7 global interrupt` 优先级 **5**；Generate 后在
  `main.c` 的 USER CODE 区恢复 `Angle_Init(); HAL_TIM_Base_Start_IT(&htim7);`
  与 `HAL_TIM_PeriodElapsedCallback` 里的 TIM7 分支（调 `Angle_Step()`）。
  ⚠ **Phase 0 未做**：`ANG_TAU_F` / `Kp_ω` / `K_ff` 的整定依赖两个尚未实测的量
  —— **OPS9 的真实帧率**（决定内环带宽上限）与 **`pose.wz` 的噪声水平**。
  `ANG_KI_W` 起步给的是 **0**（先跑通链路再加）。
  ⚠ 未按 `CLAUDE.md` §7.3 把参数收拢到 `config/param_config.h`（该文件尚不存在），
  暂放 `angle_ctrl.h`，待其落地时一并迁入。

#### V1.33.0 - 2026-10-12

- **涉及模块**：算法层 / `algorithm/angle_ctrl.c` + `.h`；应用层 /
  `app/NavigationMecanum.c` + `.h`、`app/worker_task.c`；生成区 /
  `Core/Src/main.c`、`Core/Src/stm32g4xx_it.c`、`Core/Src/app_freertos.c`
- **修改内容**：把 `Angle_Step()` 从 **TIM7 中断 (1kHz)** 搬进 **`Nav_GoToWorld()`
  的驱动循环**，与 `Mecanum_Calc_Full_V()` / `Send_commandmotor()` **同拍**。
  ① `app/NavigationMecanum.c`：`#if NAV_YAW_CASCADE` 分支里、`Angle_GetW()` 之前
     加 `Angle_Step();`（顺序要求：先 `Angle_Enable()` 再 Step，同拍生效）。
  ② `Core/Src/main.c`：`HAL_TIM_PeriodElapsedCallback` 的 TIM7 分支里那句
     `Angle_Step()` 注释掉；`USER CODE BEGIN 2` 的 `HAL_TIM_Base_Start_IT(&htim7)`
     一并注释掉 —— 否则 1kHz 空中断白烧 CPU。**回退 = 放开这两处注释。**
  ③ `algorithm/angle_ctrl.h`：**`ANG_DT` `0.00f` → `0.011f`**（★ 必改，见备注）；
     顶部「中断/任务分工」整块重写成「步进位置」，写明为什么搬回来。
  ④ `algorithm/angle_ctrl.c`：共享面注释从「任务 ↔ ISR」改成「只剩任务一个上下文」
     （`volatile` 保留，理由写进注释）；`Angle_Step()` 的 `@warning` 改成
     「保持纯计算，便于将来再挪回中断」。
  ⑤ 同步刷掉 5 处过期注释：`angle_ctrl.h` 的 `Angle_Step` 声明、`NavigationMecanum.h`
     的 `NAV_YAW_CASCADE`、`worker_task.c` 的 `Angle_Fuction`、`app_freertos.c` 的
     遥测判读提示、`stm32g4xx_it.c` 的 TIM7 handler。
- **影响范围**：**航向环的采样/计算节奏**（1 kHz → 约 90 Hz）。控制律本身的公式、
  增益、限幅**一个没动**；平移 X/Y 链未动。`g_angle_ctrl_enable` 那条历史契约路径
  （`Angle_Fuction`，本就无调用者）未动。
- **验证状态**：待测试（`--clean-first` 全量重编通过、零新增告警；`nm` 确认
  `NavigationMecanum.c.obj` 出现 `U Angle_Step`、`main.c.obj` 不再引用
  `Angle_Step` / `htim7` / `HAL_TIM_Base_Start_IT`）
- **备注**：
  ⚠ **`ANG_DT` 必须跟着改，不是可选项。** 原值 `0.00f` 让 S 型轨迹三行积分
  （`s_a += a_dot*ANG_DT` / `s_w += s_a*ANG_DT` / `s_th += s_w*ANG_DT`）**全部乘 0**
  ⇒ `s_th` 永远停在 `Angle_Enable()` 那一刻的航向、参考角不推进 ⇒ 外环误差恒 0
  ⇒ **车转不到新航向**，只会「保持进段朝向」；同时内环 I 增益 `ANG_KI_W * ANG_DT`
  也被清零（内环退化成纯 P）。搬进任务后周期 ≈ `NAV_LOOP_TICKS`(5) × 1 ms + 下发
  耗时 ⇒ 取工程原有的 `NAV_DT`(0.011f)。**实测校准入 = `[NAV] ARRIVE` 日志里的
  `dt=%.1fms`**；`NAV_LOOP_TICKS` / `NAV_DT` 一改必须同步改这里。
  ⚠ **本次未动、但已确认存在的三处**（用户明确要求"先看现象"）：
  a. `angle_ctrl.c:273` 的 `float af = ANG_DT/(ANG_TAU_F+ANG_DT);` **算完没人用**，
  `s_w_filt = p.wz;` 是直通 ⇒ **一阶低通完全没生效**，内环反馈是原始 `wz`
  （`-Wall` 已报 `unused variable 'af'`）；
  b. `ANG_W_DEADBAND = 0.5f` 作用在 `pose.wz`(rad/s) 上 = **28.6°/s** 硬死区，
  比这慢的转动内环看不见；
  c. `s_wz_bias` / `s_bias_done` **声明了但全工程零引用**（注释里引用的
  `ANG_BIAS_N` 也没定义）⇒ 注释预告的「车自己慢慢转」没人管。
  ⚠ **TIM7 腾出来了，但别顺手给 sw_uart 用**：`hardware/bus/sw_uart.c` 的
  `SW_UART_TIM` 就是 TIM7，且那边**自己也定义了一份 `TIM7_IRQHandler`**。当前不
  撞车纯属侥幸 —— `sw_uart.c` **没有 include 自己的头 `sw_uart.h`**，于是
  `#if SW_UART_ENABLE` 恒按 0 求值、**整个文件被预处理掉**（等于该驱动目前是死代码）。
  谁补上这个 include 立刻是重复定义链接错误。已在 `stm32g4xx_it.c` 的 handler 上方
  写了 `@warning` 留证。
  ⚠ 与航向无关、但同期发现的**定点跑不到位的独立原因**：`g_waypoints[]` 下标 3/4/5
  （4 亚军点 / 5 冠军点 / 6 季军点）的 `yaw` 是 **`0.0f` 占位值、从未示教**
  （`g_waypoint_count = 10u`，这几点一定会被走到）。`Angle_Enable()` 走近路到
  target=0 ⇒ 车转到 **OPS9 的 yaw = 0 方向**（该零点本身未标定）。**本次未改。**

#### V1.33.1 - 2026-10-12
- **修改类型**：删除（**去掉重复的航向到位判据**；**不兼容升级** —— 少了一个导出符号）
- **涉及模块**：算法层 / `algorithm/angle_ctrl.c` + `.h`
- **修改内容**：删掉 `Angle_Arrived()` 与 `ANG_ARRIVE_TOL`。
  ① 该函数**全工程零调用者** —— 航向"到没到位"实际一直由 `Nav_GoToWorld()` 判
     （`NavigationMecanum.c:359-363`：`|eyaw| ≤ NAV_TOL_YAW`，其中
     `eyaw = NAV_WrapPi(target_yaw − pose.yaw)`）；
  ② 两条判据**量的不是同一个东西**：导航那条判的是**对真目标**的误差，而
     `Angle_Arrived()` 判 `|s_e_th|`、即**对 S 曲线参考角**的误差 —— 只有轨迹
     收敛之后两者才相等，过渡段不等。并存只会让人搞不清谁说了算；
  ③ `s_e_th` **保留**（仍喂 `Angle_GetTelem()->e_th`，`app_freertos.c` 的调参打印
     要用），但注释改成"仅供调试打印，本模块不再自判"；
  ④ 原处留下说明注释 + 头文件留一段"为什么只留导航那一条"，防止后人再加回来。
- **影响范围**：**零行为影响**（被删函数自始无调用者）。`Angle_GetTelem()` /
  `Angle_Enable()` / `Angle_Step()` 等全部未动。
- **验证状态**：待测试（`--clean-first` 全量重编通过、零新增告警；全工程 grep 确认
  `Angle_Arrived` / `ANG_ARRIVE_TOL` 只剩两处**说明性注释**）
- **备注**：⚠ 这是**刻意的不兼容删除**。若将来真出现"不依赖导航、只想问航向环自己
  转到位没有"的需求，**不要**把 `Angle_Arrived()` 加回来 —— 那会重新制造两套判据；
  正确做法是把 `NAV_TOL_YAW` 那一条抽成公共函数。另：`NAV_TOL_YAW`(0.05 rad ≈ 2.9°)
  与原 `ANG_ARRIVE_TOL`(0.05f) **数值相同**，所以本次删除**没有**改变任何既有阈值。
  （`angle_ctrl.h` 的 `#include <stdbool.h>` 现已无本文件内的使用者，保留不动 ——
  删 Include 有连带风险，收益为零。）
