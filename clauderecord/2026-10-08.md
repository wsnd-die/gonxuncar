#### V1.28.0 - 2026-10-08
- **修改类型**：修改（**物料摆放改为"只按颜色选块"，四件都放**）
- **涉及模块**：
  - 业务层 / `app/ColorIdentif.c`、`.h`（`T1[]` 改一维颜色表；`TT_SeekBlock()` 加"已放过的槽"掩码；`TT_BlocksCoverTable()` 改按颜色对账）
  - 业务层 / `app/block_collect.c`（夹紧/识别顺序改回；`block_fill_defaults()` 注释）
  - 应用层 / `app/worker_task.c`（`NF_STAGES` 的 `FindCircle` 轮数）
- **修改内容**：

  **背景**：不再判定物块形状（形状阈值表 `Slot_Shape[]` 未标定），摆放改成
  **只按颜色选块**，并且要**四件都放出去**。

  **① `T1[]` 从 `[4][2]` 改成 `[4]` 的一维颜色表**

  ```c
  static uint8_t T1[4] = { COLOR_BLUE, COLOR_BLUE, COLOR_RED, COLOR_RED };
  ```

  `T1_ROWS = sizeof(T1)/sizeof(T1[0])` 不变（仍是 4）。

  **② `TT_SeekBlock()` 加"已放过的槽"掩码 `s_used_mask` —— 这是本次的关键**

  原先 `T1[]` 每行是 `(颜色, 形状)`，**形状那一列的唯一作用是让四行互不相同**：
  搜索总是从 `s = 1` 开始返回**第一个**匹配的槽，四行组合互不相同才能落到四个不同的槽。
  形状判定去掉后，同色的两行会**指向同一个槽** —— 一个槽被放两次，另一件永远放不出去
  （这正是"只按颜色改完只出去两件"的原因）。

  所以加 `static uint8_t s_used_mask`（bit1~4 对应 g_tt 下标 1~4 = 物理槽 2~5），
  交出去过的槽不再返回；`TT_RotateReset()` 里**跟着 `s_seek_slot` 一起清零**。
  顺带在搜索条件里补了 `TT_IsCollected(s)` —— 没采到（漏料）的槽不去。

  沿用 V1.27.0 的"搜不到时游标照样推进"，避免一行匹配不上吃掉后面所有轮次。

  **③ `TT_BlocksCoverTable()` 改成按颜色逐色对账**

  从"四个 `(颜色,形状)` 组合是否齐全"改成"`T1[]` 里每种颜色要几个、已采集的槽里
  就有几个"。`block_fill_defaults()` 用它判要不要整批走默认表 —— 它的默认配比
  `NF_DEF_COLOR = {红,红,蓝,蓝}` 正好对上 `T1[]` 的 2 红 2 蓝（注释里已写明二者
  必须一致，否则改写也白改）。

  **④ 夹紧/识别顺序改回（`block_collect.c` 的采集循环）**

  上一状态是 `identify_slot(slot); BlockBasic_GripperClamp(slot);` —— **顺序反了**。
  `identify_slot()` 第一件事是 `BlockBasic_GripperRaw(slot)`（读夹爪当前位置），
  而形状判定的前提是"**夹紧状态下**回读"（见 `block_basic.c` 的 `Slot_Shape[]` 注释）：
  后夹紧 → 读到的是松开时的空程位置，`g_tt.raw_angle` 和 `slot=..raw=..` 那行日志全废，
  阈值再也没法标定。且 `MSP_Color_Vote()` 要在里面等 `MSP_COLOR_VOTE_MS`，
  那段时间物块必须已经被夹住。**已改回 clamp → identify。**

  **⑤ `NF_STAGES` 的 `{Event_FindCircle, 3u}` → `{Event_FindCircle, 5u}`**

  3 轮是"1 黄锥 + 2 件"的配置，四件要 5 轮（1 黄锥 + `T1[]` 的 4 行）。

- **影响范围**：物料采集后的摆放阶段。奖杯分支不受影响（走 `g_tt.trophy[]`）。
  接口**兼容**：`T1[]` 是文件内 `static`，`TT_SeekBlock()` / `TT_RotateReset()` /
  `TT_BlocksCoverTable()` 签名都没变。
- **验证状态**：编译已验证（`--clean-first`，147/147，无 error、**无新增告警**；
  既有告警仍是 `app_freertos.c` 的 `test` 未使用 + `oled_data.c` 的 4 处 missing-braces）。
  **实机未验证**。
- **备注**：
  1. **形状这一维现在完全没人读了** —— `identify_slot()` 仍写 `g_tt.shape[]`、
     `Slot_Shape[]`/`BlockBasic_ShapeFromRaw()` 仍在，但 `TT_SeekBlock()` 与
     `TT_BlocksCoverTable()` 都不再看它。将来要恢复形状判定，改回这两处即可；

  3. ★ `T1[]` 与 `NF_DEF_COLOR[]` 的**配比必须一致**（都是 2 红 2 蓝）。改一个要改另一个。

     `TT_RotateReset()` 漏清。

#### V1.28.1 - 2026-10-08
- **修改类型**：修复（**`'y'` 支符号翻转**）+ 修改（**按距离切换控制律**）
- **涉及模块**：业务层 / `app/NavigationMecanum.c`（`NAV_AxisRef()`）、`app/NavigationMecanum.h`（参数）
- **修改内容**：

  **① 修复：`'y'` 支的符号翻转（本次的主要问题）**

  上一次改动在 `'y'` 分支加了一行，想让近场不受制动曲线约束：

  ```c
  float y_v  = kp * err - kd * v_now;
  float y_vc = sqrtf(2.0f * a_brk * fabsf(err));   /* 幅值, 恒 ≥ 0 */
  if (err<0.3) y_vc=y_v;        /* ← 问题在这 */
  if (y_v >  y_vc) y_v =  y_vc;
  if (y_v < -y_vc) y_v = -y_vc;
  ```

  两个致命点：

  - **判据是带符号的 `err`** → `err<0.3` 对**所有负误差**都成立，不止近场；
  - **`y_vc` 是「幅值」语义**，赋成带符号的 `y_v` 后 `-y_vc` 变成 `-y_v`。
    此时 `y_v < -y_vc` 即 `y_v < -y_v`，**恒真** → `y_v = -y_v`，**符号翻转**。

  后果：`ey < 0`（目标在 −y 方向，或已过冲到另一侧）时输出被翻成正值、再经
  `NAV_Clamp` 顶到 `+NAV_VMAX_Y`，**车朝背离目标的方向满速冲出去**（正反馈）。

  | `ey` | 原意 | 实际 |
  |---|---|---|
  | `≥ 0.3` | 制动曲线 | 制动曲线 ✓ |
  | `0 ~ 0.3` | 纯 P | 纯 P ✓ |
  | `≤ 0` | 纯 P | **符号翻转 → +2.5 m/s 反向冲** ✗ |

  **结论**：要「放开上限」只能赋**正值** `v_max`，绝不能赋 `y_v`。`'x'` 支
  本次一并改成同一套写法（它原本没这行，没受影响）。

  **② 修改：近场/远场两个控制律按 |误差| 平滑切换**

  ```
  lim_far  = √(2·a_brk·|e|)              远场律: 制动曲线上限
  lim_near = NAV_CREEP_X_V / _Y_V        近场律: 低速爬行上限
  w        = smoothstep(|e|; LO, HI)     0 = 近场, 1 = 远场
  v        = clamp(Kp·e - Kd·v_now, ±lerp(lim_near, lim_far, w))
  ```

  近场把上限压到爬行速度，末端几十厘米慢走，不再被 `Kp·e` 推着冲过容差再往回晃。

  **为什么用权重混合而不是 `if` 分段**：两条律直接 `if` 切，边界上指令是**阶跃**
  —— 以 X 轴为例，`|e|` 跨过 `LO` 时上限从 `Kp·LO` 跳到 `√(2·a·LO)`。
  `smoothstep` 两端导数为 0，边界连续且**无拐点**，不会顿挫。

  **③ 新增参数**（`NavigationMecanum.h`，全部为初值 ★待实测）

  ```c
  #define NAV_SWITCH_LO   0.05f   /* |e| ≤ LO → 纯近场律 (爬行封顶) */
  #define NAV_SWITCH_HI   0.25f   /* |e| ≥ HI → 纯远场律 (制动曲线上限) */
  #define NAV_CREEP_X_V   0.18f   /* X 轴近场爬行速度上限 m/s */
  #define NAV_CREEP_Y_V   0.18f   /* Y 轴近场爬行速度上限 m/s */
  ```

  **★ 两个爬行上限必须 < `NAV_ARRIVE_VMAX`(0.19)**，否则到位判据的
  `|v| ≤ NAV_ARRIVE_VMAX` 永远满足不了 —— 低速段 `v` 会收敛到爬行封顶值，
  而封顶值比门限还大。（已在头文件里注明。）

  按 `NAV_KP_Y_LIN=6.0` / `NAV_BRK_Y=0.7` / `NAV_VMAX_Y=2.5` 算出的新曲线：

  | `|ey|` (m) | 旧（纯制动曲线） | 新 |
  |---|---|---|
  | 0.50 | 0.84 | 0.84 |
  | 0.30 | 0.65 | 0.65 |
  | 0.15 | 0.46 | 0.32 |
  | 0.10 | 0.37 | 0.21 |
  | 0.05 | 0.26 | **0.18**（封顶） |
  | 0.02 | 0.12（P 主导） | 0.12（P 主导） |

  3 cm 以外两版一致（远场），3 cm 以内新版明显收慢，**没引入死区**
  （`e=2cm` 时 `Kp·e=0.12 < 0.18`，仍是 P 主导）。
