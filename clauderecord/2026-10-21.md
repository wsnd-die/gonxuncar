#### V1.33.6 - 2026-10-21
- **修改类型**：修复（**构建配置**：`CMakePresets.json` 里的两处硬编码绝对路径已失效，
  配置阶段直接 `FATAL_ERROR`）
- **涉及模块**：构建层 / `CMakePresets.json`（`cmake/gcc-arm-none-eabi.cmake` 与
  `CMakeLists.txt` **一行未改**）
- **修改内容**：
  1. **`ARM_TOOLCHAIN_PATH`** 原先写死 `D:/DevEnv/GNU-tools-for-STM32/bin`，该目录不存在
     ⇒ 工具链脚本命中 `message(FATAL_ERROR "arm-none-eabi toolchain not found")`。
     实际工具链在 `D:/STM32CubeCLT_1.18.0/GNU-tools-for-STM32/bin`，**本就在脚本
     `gcc-arm-none-eabi.cmake:18-22` 的 `file(GLOB CUBECLT_CANDIDATES)` 候选表里**
     （`D:/STM32CubeCLT*/GNU-tools-for-STM32/bin`）。故**删掉该缓存变量**，
     交还给脚本自动发现，而不是把 `D:/DevEnv` 换成另一条机器专属路径 ——
     换路径只是把同一个坑留给下一台机器 / 下一次重装。
  2. **`CMAKE_MAKE_PROGRAM`** 原先写死 `D:/CLion 2026.2.3.1/bin/ninja/win/x64/ninja.exe`，
     而当前装的是 CLion **2025.3.1** ⇒ `ninja --version` 直接 "no such file or directory"，
     连带 `CMAKE_C_COMPILER not set`。同样删除，让 CMake 按 PATH 找 ninja
     （本机解析到 `D:/STM32CubeCLT_1.18.0/Ninja/bin/ninja.exe`，与工具链同属 CubeCLT，版本匹配）。
  3. 这两个变量一旦进了 `CMakeCache.txt` 就**不会**因为从预设里删掉而消失（缓存优先级高于预设），
     故同时清掉了 `build/Debug` 与 `build/Release` 的旧缓存。
     `build/Release/CMakeCache.txt` 另有一处更早的污染：它记录的是
     **另一条机器路径 `d:/cubeide/xianmu/bydcar_g491vet6/build/Release`**，
     不清理会报 "source ... does not match the source ... used to generate cache"。
- **影响范围**：仅配置/生成阶段。编译选项、链接脚本、源码 glob、产物路径一律未变。
- **验证状态**：已验证
  - `cmake -DCMAKE_BUILD_TYPE=Debug --preset Debug` → 编译器识别为 `GNU 13.3.1`，
    路径 `D:/STM32CubeCLT_1.18.0/GNU-tools-for-STM32/bin/arm-none-eabi-gcc.exe`，配置通过；
  - `cmake --build --preset Debug` 全量 148 个目标**构建通过**，链接产出
    `bydcar_g491vet6.elf`：FLASH 74220 B / 512 KB（14.16%）、RAM 25576 B / 96 KB（26.02%）；
  - `--preset Release` 配置通过（未构建）；
  - 剩余告警均为 V1.31.2 已记录的既有项（`oled_data.c` `-Wmissing-braces` ×4、
    链接期 RWX LOAD segment），**无新增告警**。
- **备注**：
  - 若将来再换 CLion / CubeCLT 版本，只要它们装在被 glob 覆盖的位置或 ninja 在 PATH 上，
    本次改动**无需再动**；确实需要覆盖时仍可用
    `cmake -DARM_TOOLCHAIN_PATH=... --preset Debug` 命令行临时指定（脚本第 17 行的
    `if(NOT DEFINED ARM_TOOLCHAIN_PATH)` 会优先采用）。
  - **CLion 侧还需注意**：IDE 读的是它自己缓存过的 CMake profile。若重启后仍报旧路径，
    在 `Settings → Build, Execution, Deployment → CMake` 里把该 profile 的
    "CMake options" 清空 / 重新加载 CMake 项目（Tools → CMake → Reset Cache and Reload），
    让它重新从 `CMakePresets.json` 读取。

#### V1.34.0 - 2026-10-21

  - 业务层：新增 `algorithm/map.c/.h`（9 节点 + Dijkstra）、`algorithm/chassis.c/.h`（里程计闭环点任务）、`algorithm/vision_align.c/.h`
  - 抽象设备层：新增 `device/imu_world.c/.h`、`device/uart_dispatch.c/.h`
  - 硬件驱动层：重写 `hardware/sensors/k230.c/.h`（UART4 ASCII 协议）；新增
    `hardware/actuators/servo_pwm.c/.h`、`hardware/actuators/manipulator.c/.h`、
    `hardware/display/hmi_protocol.c/.h`、`hardware/display/hmi_display.c/.h`
  - 调试：新增 `debug/vofa_debug.c/.h`（精简版）
  - 配置：新增 `config/robot_config.h`
  - Core：`main.c`、`app_freertos.c`、`usart.c`、`tim.c`、`can.c`、`usart.h`、`FreeRTOSConfig.h`
  - 构建：`CMakeLists.txt`、`gonxuncar_g491vet6.ioc`
- **修改内容**：
  1. 删除旧奖杯/物块比赛流程：`worker_task`、`ColorIdentif`、`block_collect`、
     `NavigationMecanum`、`banyuntask`、`Circle_base`、`arc_path`、`angle_ctrl`、`pid`、
     `block_basic`、`servo_scs` + `scslib`、`collect_ir`、`color`、`msp_color`、`grayscale`、
     `QRcode`、`NX_uart`、`ops9_g491_uart3`、`uart2_tbop10`、`sw_uart`、`oled`、`ws2812`、`key`。
  2. 新流程：启停区 → N6 扫码(2s 占位) → N8 原料1 → N2 粗加工1 → N4 暂存1 →
     N8 原料2 → N2 粗加工2 → N4 暂存2 → 回程路口 → 启停区。
  3. 定位：放弃 OPS9，改用**速度模式 + 四轮编码器里程计**（沿用 `locator_wheel`）+ HWT906 航向。
  4. 底盘对上层只暴露点任务：`Chassis_GotoNode/GotoWorld/MoveBody/RotateTo/Stop`，
     与云台/夹爪/料盘完全解耦，可在 `APP_Task()` 里注释切换 `Test_Chassis` /
     `Test_Manipulator` / `Test_Vision` / `Mission_Run`。
  5. 机械臂改为参考工程那套：TIM3 CH2/CH3/CH4 三路 PWM 舵机 + CAN ID5/ID6，
     只保留任务用到的 4 条动作序列（取料/放料/叠放/回零）。
  6. K230 改为 UART4 ASCII 行协议（detect/place/stack/stop）。
  7. HMI 串口屏走 USART3（AA 55 帧解析 + Nextion 显示指令）。
  8. 引脚对齐参考工程：USART2 TX 由 PD5 改 **PA2**；TIM3 CH2/CH3 新增 **PE3/PE4**；
     UART4=K230、USART3=HMI、UART5=VOFA、FDCAN2 不变。
  9. FreeRTOS 精简为 defaultTask + `APP_TASK` + `IMU_TASK`；堆 16KB→32KB。
  10. `can.c` 的 0x3A 回帧解析改为同时兼容 `[3A][status][6B]` 与旧 `[3A][01][status][6B]`。
- **影响范围**：整个比赛应用层与机械臂/K230/HMI 驱动；底盘运动学、EMM 驱动、HWT906 驱动保持原实现。
- **验证状态**：已验证（静态）—— `cmake --build --preset Debug --clean-first` 全量通过，
  **零新增告警**（仅剩既有的 RWX LOAD segment 告警）；`nm -u` 无未解析应用符号；
  FLASH 65996 B / RAM 41416 B。**实机未验证**。

    底盘几何参数、9 节点坐标、新舵机中位/行程、HMI 页面控件名。
  - 扫码仍是 2 s 占位；颜色写死为第一批 1/2/3、第二批 4/5/6。
  - `manipulator.c` 假定上电时云台在最高点、滑台在机械原点；不在原点时先人工归零。
