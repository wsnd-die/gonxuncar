#### V1.33.6 - 2026-10-21
- **修改类型**：修复（**构建配置**：`CMakePresets.json` 里的两处硬编码绝对路径已失效，
  配置阶段直接 `FATAL_ERROR`）
- **涉及模块**：构建层 / `CMakePresets.json`（`cmake/gcc-arm-none-eabi.cmake` 与
  `CMakeLists.txt` **一行未改**）
- **修改内容**：
  1. **`ARM_TOOLCHAIN_PATH`** 原先写死 `D:/DevEnv/GNU-tools-for-STM32/bin`，该目录不存在
     ⇒ 工具链脚本命中 `message(FATAL_ERROR "arm-none-eabi toolchain not found")`。
     实际工具链在 `D:/STM32CubeCLT_1.18.0/GNU-tools-for-STM32/bin`，**本就在脚本
     `gcc-arm-none-eabi.cmake:18-22` 的 `file(GLOB CUBECLT_CANDIDATES)` 候选表里**
     （`D:/STM32CubeCLT*/GNU-tools-for-STM32/bin`）。故**删掉该缓存变量**，
     交还给脚本自动发现，而不是把 `D:/DevEnv` 换成另一条机器专属路径 ——
     换路径只是把同一个坑留给下一台机器 / 下一次重装。
  2. **`CMAKE_MAKE_PROGRAM`** 原先写死 `D:/CLion 2026.2.3.1/bin/ninja/win/x64/ninja.exe`，
     而当前装的是 CLion **2025.3.1** ⇒ `ninja --version` 直接 "no such file or directory"，
     连带 `CMAKE_C_COMPILER not set`。同样删除，让 CMake 按 PATH 找 ninja
     （本机解析到 `D:/STM32CubeCLT_1.18.0/Ninja/bin/ninja.exe`，与工具链同属 CubeCLT，版本匹配）。
  3. 这两个变量一旦进了 `CMakeCache.txt` 就**不会**因为从预设里删掉而消失（缓存优先级高于预设），
     故同时清掉了 `build/Debug` 与 `build/Release` 的旧缓存。
     `build/Release/CMakeCache.txt` 另有一处更早的污染：它记录的是
     **另一条机器路径 `d:/cubeide/xianmu/bydcar_g491vet6/build/Release`**，
     不清理会报 "source ... does not match the source ... used to generate cache"。
- **影响范围**：仅配置/生成阶段。编译选项、链接脚本、源码 glob、产物路径一律未变。
- **验证状态**：已验证
  - `cmake -DCMAKE_BUILD_TYPE=Debug --preset Debug` → 编译器识别为 `GNU 13.3.1`，
    路径 `D:/STM32CubeCLT_1.18.0/GNU-tools-for-STM32/bin/arm-none-eabi-gcc.exe`，配置通过；
  - `cmake --build --preset Debug` 全量 148 个目标**构建通过**，链接产出
    `bydcar_g491vet6.elf`：FLASH 74220 B / 512 KB（14.16%）、RAM 25576 B / 96 KB（26.02%）；
  - `--preset Release` 配置通过（未构建）；
  - 剩余告警均为 V1.31.2 已记录的既有项（`oled_data.c` `-Wmissing-braces` ×4、
    链接期 RWX LOAD segment），**无新增告警**。
- **备注**：
  - 若将来再换 CLion / CubeCLT 版本，只要它们装在被 glob 覆盖的位置或 ninja 在 PATH 上，
    本次改动**无需再动**；确实需要覆盖时仍可用
    `cmake -DARM_TOOLCHAIN_PATH=... --preset Debug` 命令行临时指定（脚本第 17 行的
    `if(NOT DEFINED ARM_TOOLCHAIN_PATH)` 会优先采用）。
  - **CLion 侧还需注意**：IDE 读的是它自己缓存过的 CMake profile。若重启后仍报旧路径，
    在 `Settings → Build, Execution, Deployment → CMake` 里把该 profile 的
    "CMake options" 清空 / 重新加载 CMake 项目（Tools → CMake → Reset Cache and Reload），
    让它重新从 `CMakePresets.json` 读取。
