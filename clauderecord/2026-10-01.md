#### V1.19.8 - 2026-10-01
- **修改类型**：修改（**不兼容升级** —— `Arc_Run()` 的输出路径与依赖整体更换）
- **涉及模块**：
  - 业务层 / `algorithm/arc_path.c`
  - 业务层 / `algorithm/arc_path.h`
- **修改内容**：

  **背景**：`app/worker_task.c` 在 2026-10-01 的精简中删除了 `g_angle_ctrl_speed`
  与 `g_angle_ctrl_w_ff` 的定义（角度环只保留纯转向，`Angle_Fuction` 里改成了
  `Mecanum_Calc(0, s_fc.cmd_w)`）。`arc_path.c` 仍在引用这两个量 → **链接失败**
  （`undefined reference to g_angle_ctrl_speed / g_angle_ctrl_w_ff`）。且即使补回定义，
  线速度恒 0 也让圆弧退化成原地自转。

  经确认（用户选择「圆弧自己发指令」+「纯几何开环」），把圆弧改为**自持电机指令源**：

  - `Arc_Run()` 不再走 `g_angle_ctrl_*` 契约量、不再依赖 FC_TASK 与 IMU，改为自己
    `Mecanum_Calc(v, w_rad)` + `Send_commandmotor()`，主循环每拍重发防丢帧；
  - 计时判据由「切向角推进 `w_deg * t >= sweep`」改为等价的「时间 `t >= sweep_time_s`」
    （开环下发，几何已锁定，无需再读航向）；
  - `Arc_Abort()` 改为置 `g_angle_ctrl_enable = 0` 后直接发零速；
  - 新增 `static void ARC_Stop()`（零速下发）；
  - 去掉 `#include "HWT906.h"` / `#include "hwt_imu.h"` 与 `ARC_IMU_WAIT_MS` 宏
    （开环不再等 IMU 有效）；
  - `arc_path.h` 文件头重写：删除「前馈 + PID 分工」一节，改为说明**开环会累积
    航向误差、轨迹会偏**；两条 `@warning` 保留（电机指令源唯一、符号是生死线）。

- **影响范围**：
  - 调用方 `app/worker_task.c` 的 `Event_ArcRun` 分支行为改变 —— 圆弧期间不再由
    FC_TASK 产出指令；圆弧执行期间**航向无反馈修正**，轨迹可能偏移。
  - `worker_task.h` 的 `g_angle_ctrl_speed` / `g_angle_ctrl_w_ff` 两个 `extern`
    目前**已无任何引用**（定义已删、引用已删），属悬空声明，待清理。
- **验证状态**：**编译已验证**（`cmake --build --preset Debug` 通过，无新增告警）；
  **实机未验证** —— 符号方向、轨迹准确性均未上机测试。
- **备注**：⚠ 开环圆弧的航向误差不收敛，这是用户明确选择的形态。若后续发现轨迹
  发散，需在外层补航向反馈（可复用 `AngleCtrl`，注意其中层限幅 `CFG_MAX_W_DEG = 10°/s`
  低于圆弧所需角速度，会饱和）。

  **物块收集**：IR 检测到物块 → 夹紧该槽夹爪 → 回读 SCS0009 原始位置（判长方体/圆柱）
  → 读 MSP 芯片回传的颜色 → 按槽位存进 `g_tt` → 转盘转下一槽。跑物理槽 2~5 一轮即停。
  物理槽 1 固定是黄色圆锥，不夹不读、不写进 `g_tt`。

  1. **`msp_color.c/.h`（新建）** —— 仓库里此前**没有任何 MSP 接收代码**（`uart/msp_uart2.c`
     只是个空壳）。新驱动走 USART2（RX = PA3）**DMA + IDLE**，收 `'r'`→红、`'b'`→蓝，
     其余字符计入 `rx_unknown`。挂在 `Core/Src/usart.c` 那个唯一的
     `HAL_UARTEx_RxEventCallback` 分发器的 USART2 分支上（该分支此前被
     `#if LEGACY_USART2_ODOM_ENABLE`（=0）编译掉）。`MSP_Color_Init()` 在
     `USER CODE BEGIN USART2_Init 2` 里调。**不影响同一串口上的 `printf`** ——
     TX 走 `gState`、RX 走 `RxState`，HAL 里是两套独立状态机。
  2. **`block_collect.c/.h`（新建）** —— 收集状态机，自带 `for(;;)` 任务
     （结构照角度环），任务在 `USER CODE BEGIN RTOS_THREADS` 里创建
     （`Normal/24`，2KB 栈）。超时未收到颜色时回退默认值：槽 2/3 = 红、槽 4/5 = 蓝
     （比赛保证槽 2~5 恰为 2 红 2 蓝）。
  3. **`block_basic`** —— 新增 `BlockBasic_GripperClamp/Release/Raw`、
     `BlockShape_t`、`BlockBasic_ShapeFromRaw()` 与阈值 `BLOCK_SHAPE_RAW_THRESHOLD`
     （**占位值 620，★必须实测标定**）。形状判定里 `raw < 0` 先返回 `SHAPE_UNKNOWN`，
     否则总线失败（`Scs0009_ReadRaw` 返回 -1）会被误判成圆柱。
  4. **`TT_t` 追加** `shape[5]` / `raw_angle[5]` / `collected`（只能往后加），
     配 `TT_SetShape/TT_SetRawAngle/TT_SetCollected/ShapeAtSlot/RawAngleAtSlot/TT_IsCollected`。
     有效性一律以 `collected` 位为准 —— `TT_Init()` 是 `memset(0)`，`raw_angle` 初值是 0 不是 -1。
  5. **流程**：`Event_Collect = 12`（追加）；`NF_Stage_Collect()` 把采集丢给 blockcol 任务
     并轮询完成标志，然后落回 `Event_Navigation`。**`NF_STAGES[]` 临时单站表原样未动**，
     两边共存。启动键 PA0 由发 `Event_Navigation` 改成发 `Event_Collect`。
  6. **清理**：删除 `uart/msp_uart2.c/.h`（含 `CMakeLists.txt` 两行；该头文件里是
     **定义**而非声明，被第二个 TU 包含就是重复符号错误）；删除
     `Collect_ReadColor/Collect_ReadColor_NB/Collect_WaitObject`（它们依赖的
     `g_uart2_gy33_*` 只在注释里定义，**一旦被调用就链接失败**，
     此前靠 `--gc-sections` 整段丢弃才没炸）；`gripper_task` 的死轮询循环删除
     （其 `raw[]` 与 `IR_ObjectEntered()` 返回值都是丢的，且它是 `IR_ObjectEntered()`
     的第二个调用者，而那个函数有 static 上一拍状态，两个调用者会互相破坏），
     只留初始化 + 心跳。

- **影响范围**：
  - 启动键 PA0 的行为变了 —— 现在先跑采集再进原顺序表。
  - `gripper_task` 不再占用舵机总线、不再读舵机位置。

#### V1.20.1 - 2026-10-01
- **修改类型**：修改（**V1.20.0 的设计修正** —— 不新增任务，改为在 `gripper_task` 循环里轮询）
- **涉及模块**：
  - 应用层 / `app/block_collect.c`、`.h`
  - Core / `Core/Src/app_freertos.c`
- **修改内容**：

  V1.20.0 给采集单独创建了一个 `blockcol` FreeRTOS 任务
  （`USER CODE BEGIN RTOS_THREADS` 里 `osThreadNew` + 一份 `osThreadAttr_t`）。
  **这是多余的** —— 按用户要求（2026-10-01）改回单任务：

  - `block_collect.c`：`BlockCollect_Task(void *)` 换成 **`BlockCollect_Poll(void)`**。
    没有采集请求时立刻返回（常态空转）；有请求时这一拍阻塞跑完整轮采集。
    逻辑体 `collect_all_slots()` 一行未改。
  - 去掉 `#include "servo_scs.h"` 与入口处那段 `while (!SCS_IsReady())` 等待 ——
    舵机总线本来就归 `gripper_task` 管（`SCS_BusInit()` 在它入口），
    采集逻辑跑在它的循环里，轮到 `Poll()` 时总线必然已就绪。
  - `app_freertos.c`：删除 `blockcol_attributes` 与那条 `osThreadNew`；
    `gripper_task` 的循环体由 `for (;;) osDelay(1000);`（V1.20.0 留的心跳）
    换成 `for (;;) { BlockCollect_Poll(); osDelay(20); }`。
  - `NF_Stage_Collect()` 与 `Event_Collect` 触发链**未动** —— 它本来就只调
    `BlockCollect_Start()` / `IsDone()`，与实现是任务还是轮询无关。

- **影响范围**：
  - 少一个任务、少 2KB 栈占用；`gripper_task` 恢复成实际干活的任务
    （V1.20.0 里它只剩初始化 + 心跳）。
  - 采集期间 `gripper_task` 会阻塞几十秒（最长 4 × `COLLECT_IR_TIMEOUT_MS`）。
    它在 `osPriorityNormal`，不挡 `NLF_TASK`(High) 里的 `NF_Stage_Collect()` 轮询。
- **验证状态**：**编译已验证**（`cmake --build --preset Debug --clean-first` 通过，
  `BlockCollect_Task` 符号已消失、`BlockCollect_Poll` 已链接，无未定义符号）。
  **实机仍未验证** —— V1.20.0 备注里的 8 条上机事项原样有效。

#### V1.20.2 - 2026-10-01
- **修改类型**：修复（**链接失败**）
- **涉及模块**：
  - 硬件驱动层 / `hardware/actuators/block_basic.h`

- **修改内容**：

  **现象**：链接失败 —— `multiple definition of 'Slot_Shape'`，报在
  `block_basic.h:96`，`app_freertos.c.obj` 首次定义，`ColorIdentif.c.obj` /
  `block_collect.c.obj` / `worker_task.c.obj` / `block_basic.c.obj` 重复定义。

  **根因**：`int Slot_Shape[4]={460,462,472,468};` 写在**头文件**里。
  带初始化器的文件作用域数组是**定义**不是声明，被 N 个 `.c` 包含就生成 N 份，
  GCC 10 起 `-fno-common` 是默认，直接报重复定义。与此前 `uart/msp_uart2.h`
  里那两个「头文件中的定义」是同一个坑（V1.20.0 已删）。

  **改法**（行为等价，索引约定不变）：

  - 阈值表从 `block_basic.h` 移入 `block_basic.c`，并加 `static const`：
    `static const int Slot_Shape[SLOT_SHAPE_COUNT] = { 460, 462, 472, 468 };`
  - 新增 `SLOT_SHAPE_FIRST = 2u` / `SLOT_SHAPE_COUNT = 4u`，下标换算由字面量
    `slot-2` 改成 `slot - SLOT_SHAPE_FIRST`（物理槽 2~5 → 下标 0~3，与原写法一致）。
  - `BlockBasic_ShapeFromRaw()` 补**槽号越界保护**：原先只挡 `raw_angle < 0`，
    槽号传成 0/1/6 会越界读 `Slot_Shape`。现在槽号不在 2~5 一律返回 `SHAPE_UNKNOWN`。
  - 加 `_Static_assert` 防住「阈值表长度」与「转盘槽位上限」脱节。
  - 头文件只留注释说明表在 `.c` 里。

- **影响范围**：仅形状判定的取值路径；`SHAPE_RECT/SHAPE_CYLINDER` 的判据与阈值
  数值一字未改（仍是 `raw >= Slot_Shape[slot-2]` → 长方体）。
- **验证状态**：**编译已验证**（`cmake --build --preset Debug --clean-first` 通过，
  无未定义符号，无新增告警）。**阈值方向与数值均未实机验证。**
- **备注**：⚠ 这 4 个阈值（460/462/472/468）比 `SCS_CLOSE`(450) 只高十几，
  密集且接近空夹位置。上机标定时注意确认 `raw >= 阈值` 到底代表「有物块」还是
  「是长方体」—— 若空夹也能量到 ~455，这个判据会把「夹到东西」误判成「长方体」。

#### V1.20.3 - 2026-10-01
- **修改类型**：修改（**采集时序重排**，不兼容 —— 动作顺序与旧版相反）
- **涉及模块**：
  - 应用层 / `app/block_collect.c`、`.h`
  - 硬件驱动层 / `hardware/actuators/block_basic.h`（新增关门角度常量）
- **修改内容**：

  **背景**：V1.20.0 的时序是「转盘就位 → 等 IR → 夹紧 → 立刻读形状+颜色」，
  与实机不符。按用户描述（2026-10-01）**颜色传感器装在「转盘转过一步之后」
  那颗物块停的位置上**，所以夹完立刻读色只会读到别的槽。改为**夹和识别错开一拍**：

  ```
  圆锥进 → IR → 转到槽 2                      [不夹不识别]
  块2进  → IR → 夹紧槽2 → 转到槽3 → 识别槽2
  块3进  → IR → 夹紧槽3 → 转到槽4 → 识别槽3
  块4进  → IR → 夹紧槽4 → 转到槽5 → 识别槽4
  块5进  → IR → 夹紧槽5 → 转 340°关门 → 识别槽5
  ```

  - 抽出 `identify_slot(slot)`：读 raw + 判形状 + 读色 + 写 `g_tt` + 打印，
    在「转到位且停稳」之后调用。
  - 圆锥单独走一段：`wait_block_entered()` 确认它来了，然后
    `BlockBasic_TurntableTo(COLLECT_FIRST_SLOT)` 把它带到槽 2。**不显式回零** ——
    上电时 `gripper_task` 的 `Servo_Angle(BLOCK_TURNTABLE_HOME_DEG)` 已经把
    转盘停在槽 1（14°）。
  - 圆锥没等到就直接 `return` 放弃整轮：它的槽位号错位会让后面全对不上。
  - 第 5 个没有「下一槽」可转，改为 `Servo_Angle(BLOCK_TURNTABLE_DOOR_DEG)`
    顺手关门。该常量放在 `block_basic.h`：
    `340 = HOME(14) + 4 × STEP(72) [槽5] + 38`，那 38° 原样来自
    `Core/Src/app_freertos.c` 里注释掉的 `// Servo_Angle(340);`。
