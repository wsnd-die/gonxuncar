#### V1.31.1 - 2026-10-11
- **修改类型**：修复（找圆跟随的**平均圆心偏差**与**系数语义**）
- **涉及模块**：算法层 / `algorithm/Circle_base.c` + `Circle_base.h`；
  应用层 / `app/worker_task.c`（`NF_Stage_PlaceDown`）
- **修改内容**：通读找圆链路（`NX_uart` 状态机 → `Circle_Follow()` →
  `NF_Stage_FindCircle()` / `NF_Stage_PlaceDown()`）后发现三处：
  ① **`g_circle_avg_x/y` 平均值偏小**（本次修）：原实现里第一拍 `'O'` 因
     `Dir_flag==0` 被跳过**不累加**，而除数写死成 `CIRCLE_O_STABLE_CNT = 2`
     —— 2 次确认只累加了 1 个样本却除以 2，**平均值只有实际值的一半**。
     而 `g_circle_avg_*` 是两条放置路径（`NF_Stage_FindCircle()` 行 561、
     `NF_Stage_PlaceDown()` 行 618）传给 `Place()` 的圆心偏差 ⇒ 最后那步
     对准/补偿一直按"偏差减半"来做。改为：**每拍都累加，除数用实际累加拍数，
     先算平均再清零**；顺手删掉已无用的 `Dir_flag` 门闩。
  ② **"先清零再求平均 → 恒为 (0,0)"**：这条**在本次之前已被修好**（求平均
     在清零之前），本次保持并补注释说明。⚠ 这一条如果还在，影响是"偏差恒 0"，
     比 ① 更严重 —— 记录在此以便回溯。
  ③ **`g_circle_speed` 是死代码 + 名字误导**（本次清理）：`NF_Stage_PlaceDown()`
     里有 `g_circle_speed = 1.0f;`。该变量实际是**「像素偏差 → m/s」的线性
     系数**（不是"速度系数"），`Circle_Follow()` **每一拍都会重算它**
     ⇒ 外部赋值下一拍就被覆盖，**是死代码**（所以并未实际造成"20m/s 冲车"，
     但它看起来像灾难，容易误导后人）。改为：
     · 改名 `g_circle_speed` → **`g_circle_k`**（全工程 6 处）；
     · 删掉 `NF_Stage_PlaceDown()` 里那句赋值，换成说明注释。
  另：`CIRCLE_XY_FAST_TH` 的注释曾写 ">20px"，实际是 **10px** —— 已改正，
  并注明两档之间是 **2.2 倍阶跃**（圆心在阈值附近抖动时速度会跳，
  想更顺可改连续插值）。
- **影响范围**：找圆阶段的最后对准/补偿量（`Place()` 的 x/y 参数）；
  两条放置路径都受影响
- **验证状态**：待测试（`--clean-first` 全量重编通过）
- **备注**：本次**没有**动控制律本身 —— `Circle_Follow()` 的移动律仍是纯比例
  （`vx = cy × g_circle_k`、`vy = cx × g_circle_k`），那段落注释掉的 `switch(dir)`
  仍是历史遗留（方向字符现在只用于判断"是否居中"）。若要更稳，可考虑把居中
  判据从"连续 N 次 `'O'`"改成"`'O'` **且** `|(cx,cy)| < 阈值`" —— 目前两者
  之间没有交叉校验。

#### V1.31.2 - 2026-10-11
- **修改类型**：修复（**负数字面量误带 `u` 后缀**）
- **涉及模块**：应用层 / `app/worker_task.c`（`NF_PLACE_HEIGHT[]`）
- **修改内容**：编译报三处 `-Woverflow`：
  ```
  worker_task.c:184: warning: overflow in conversion from 'unsigned int' to
      'short int' changes value from '4294967287' to '-9'
  static const int16_t NF_PLACE_HEIGHT[4] = { 0u, -9u, -7u, -5u };
  ```
  根因：**负数字面量带了 `u` 后缀** —— `-9u` 先算 `-9`、再套 `u`，变成
  `(unsigned)(-9) = 4294967287`，**不再是负数**；再窄化到 `int16_t` 就是溢出。
  编译器恰好截回 `-9`，**结果侥幸是对的**，但已属 UB 边缘（换编译器版本/优化
  等级就可能变），而且每次编译都刷三条告警。
  改为 **`{ 0, -9, -7, -5 }`**（去掉 `u` 后缀）。全工程扫过一遍，只此一处。
- **影响范围**：各奖杯放置时的丝杆高度表（数值不变）
- **验证状态**：已编译验证 —— `--clean-first` 全量重编，`-Woverflow` 三条告警消失
- **备注**：清理后工程剩余告警均为**既有的、与本次无关**项：
  `app_freertos.c` 的 `unused variable 'test'`、`block_collect.c` 的
  `'s_done' initialized and declared 'extern'`、`oled_data.c` 的
  `missing braces`（4 处）、以及链接期的 `LOAD segment with RWX permissions`
  （信息性）。这些可以在后续单独清理。
